## 2. 底板引脚占用表 ⭐

**这张表是接线的唯一依据。** 全部来自官方 Wiki 各实验章节原文。`【原文】`

| 功能 | 引脚 | 备注 |
|---|---|---|
| **模拟输入（ADC）** | **PA3** | ADC12_IN3。底板只有**一路**模拟输入 |
| **测频 / 比较器输出** | **PA6** | LM393 输出 → **TIM3_CH1** 输入捕获（PA6 在 F103 上只有这一个定时器功能） |
| LCD SPI0 SCK | PA5 | AF0 |
| LCD SPI0 MOSI | PA7 | AF0。**未引出 MISO** |
| LCD RES / DC / CS / BL | PB5 / PB6 / PB7 / PB8 | 顺序与上游固件一致 |
| PWM 输出（外接排针） | **PA2** | TIM2_CH3，板上简易函数发生器 |
| **EC11 编码器 A 相** | **PB4** | 带上拉，EXTI 双边沿 |
| **EC11 编码器 B 相** | **PB3** | 带上拉，方向判据 |
| **EC11 按下** | **PB9** | 上拉输入，按下拉低 |
| 三个独立按键 | PB13 / PB14 / PB15 | 一侧接地，软件消抖 |
| 底板 LED2 / LED3 | PC14 / PC15 | **低电平点亮** |
| 串口 | PA9 (TX) / PA10 (RX) | USART1 |

> **EC11 那三行与 LCD 的脚序来自上游固件源码**（`STM32-Oscilloscope` 的
> `Core/Src/gpio.c` 与 `Hardware/src/tft_init.c`），不是官方 Wiki 的引脚表 ——
> 标 `【佐证】`。Wiki 表里没有编码器。

### 🚫 硬冲突：绝对不要用 USART2

**PA2 和 PA3 都被底板占用**（PA2 = PWM 输出，PA3 = 模拟输入）。
USART2 正是 `PA2/PA3` → **USART2 在这个组合上完全不可用。**

这条不是"建议"，是硬冲突。谁要是把上位机链路选到 USART2，会同时毁掉模拟输入和 PWM。

## 4. 链路选型：USART1 + 外接 CH340 为主，USB CDC 为备

> 链路选型的历次结论：[ADR-009](06-decisions.md) → [ADR-012](06-decisions.md#adr-012--换用带板载-usb-转串口的最小系统板取代-adr-009) → [ADR-013](06-decisions.md#adr-013--串口链路用外接-ch340-模块取代-adr-012-的板载桥前提)（当前结论由最后一条决定）。

**现状（2026-10-05 校正）**：串口经**外接 CH340 模块**接到 USART1，需要接四根线；
不能只插一根 Type-C 就有 COM 口。

| 优先级 | 链路 | 引脚 | 场合 |
|---|---|---|---|
| **主力** | **USART1 + 外接 CH340 模块** | PA9 (TX) / PA10 (RX) | 四根线：模块 TX→PA10、模块 RX→PA9、GND↔GND、VCC；带宽 92 KB/s @921600 |
| 备选 | USB CDC | PA11 / PA12 | 带宽 500–900 KB/s，但要自己写 USB device 固件 |
| 🚫 **禁止** | ~~USART2~~ | ~~PA2 / PA3~~ | 硬冲突，见 §2「硬冲突：绝对不要用 USART2」 |

两条链路在操作系统层**都是 COM 口** → 同一个 `SerialDevice` 实现覆盖两者，
协议层一个字都不用改。

> ⚠️ 注意：F103C8T6 的系统 ROM bootloader 是否支持原生 USB DFU 存在争议，
> **不要把"USB DFU 一键下载"当可靠前提** `【佐证】`。

## 5. 模拟前端（底板）

来自官方 Wiki 原图与 BOM：`【原文】`

```
BNC ──► SW3（X1 直连 / X50 衰减）──► SW2（AC/DC 耦合）──► TL072IP ──► PA3
                                                            │
                                                            └──► LM393P ──► PA6
```

| 环节 | 器件 | 参数 |
|---|---|---|
| 耦合 | SW2 + 100 nF | AC 耦合隔直；原文按自谐振频率论证 100 nF 足够 |
| 衰减 | SW3 + 分压网络 | 直连（X1）或 `20k/(510k+470k+20k) = 1/50` |
| 缓冲/放大 | TL072IP | 一路跟随器，一路比例放大 `Vo=(5−Vin)/2` |
| 量程 | — | 低压 **−1.6 V ~ 5 V**；高压 **−80 V ~ 250 V** |
| 比较器 | LM393P | 滞回，`Uth=2.214 V / Utl=2.172 V` → PA6 输入捕获 |
| 负压 | XD7660 + 2 电容 + 1N4148 | 理论 −5 V，实测约 −4.3 V，供运放处理负半周 |

### ⚠️ 量程切换是机械拨动开关

**SW2（AC/DC）与 SW3（X1/X50）都是手拨的机械开关，AI 无法程控。**
要支持自动量程必须改板（换继电器/模拟开关，如 CD4053）。

> 这是一条**硬件**约束，不是软件待办 —— 决策记录里没有对应条目（ADR-001~011
> 都不涉及量程开关）。相关讨论在本节与 [`README`](../README.md) 的「硬件上必须
> 先知道的三件事」第 3 条。

### ⚠️ TL072 带宽偏软

TL072 的 GBW 只有 3 MHz，对 400 kHz I2C 的 300 ns 边沿已经偏软，
1 MHz 的 120 ns 边沿完全不够。`【推断】`
这正是 ADR-005 把协议解码放到**数字通路**（LM393 → 输入捕获）的原因之一 ——
数字通路不经过 TL072。

## 7. 🚧 待决策：单通道 vs 双通道

**底板只有一路模拟输入**（BNC → TL072 → PA3），
而 I2C 解码需要 SCL/SDA **两路同时刻采样**（时差必须 ≪ tSU;DAT：
标准 250 ns / 快速 100 ns）。`【原文】`

三个候选方案（① 改板加第二路前端 / ② 单通道 ADC + 一路数字捕获 / ③ 纯数字双通路）
的对比、P0–P3 与 P4 的建议，以及「为什么要保留模拟通路」的取舍见
[ADR-010](06-decisions.md)。**第二路 ADC 不能用 PA6** —— 它已被 LM393 的输入捕获占用（§2）。

## 9. 实板必测清单

拿到板子后**第一件事**，逐条量并回写到本文： `【待测】`

| # | 测什么 | 为什么 |
|---|---|---|
| 1 | 核心板**到底有没有**板载 USB 转串口；有的话芯片型号与最高可靠波特率 | 决定「插上 Type-C 即出 COM 口」这句话还能不能写；也决定 §4 是否改为板载桥方案 |
| 2 | 外接 CH340 模块的**最高可靠波特率** | 决定 921600 能不能用；`04-performance.md` §4 的标注据此订正 |
| 3 | SWD 调试口是否引出，丝印与脚序 | 决定能否用 DAP-Link 烧录 |
| 4 | 晶振频率（HSE 是否 8 MHz、LSE 是否 32.768 kHz） | 决定 857 kSPS 档位的时基 |
| 5 | BOOT 选择的形式（跳线还是按键） | 决定串口 ISP 是否可用 |
| 6 | 用户 LED 的引脚与极性 | 决定板级指示灯怎么写 |
| 7 | PA12 是否有 1.5 kΩ 硬上拉 | 硬上拉会导致"上电后要复位一次才能被识别"，影响 USB CDC 备选方案 |
| 8 | 核心板与底板之间是否存在 5V 倒灌路径 | 两块板各带一个 Type-C；同时接入时 5V 是否经排针互灌，取决于当前核心板的电源拓扑 |
| 9 | TL072 输出的实际源阻抗 | 决定 ADC 采样时间档（1.5 周期要求 ≤0.4 kΩ，7.5 周期放宽到 ~19 kΩ） |
| 10 | LM393 输出到 PA6 的实际阈值与边沿 | 验证数字通路可用性 |
| 11 | 8 MHz HSE 实际频率与精度 | 决定 857 kSPS 采样率与 I2C 解码的相位稳定性 |
| 12 | 底板 PA3 处的直流工作点 | 验证 `Vo=(5−Vin)/2` 的中点是否为 2.5 V |

**测完请更新本文并去掉对应的 `【待测】` 标记** —— 这是团队纪律的一部分。
