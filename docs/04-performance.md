# 04 · 性能边界（实测版）

> 这份文档的作用是**防止后期扯皮**。
> 每个「做不到」都附了物理推导；当有人质疑「为什么才这么点」时，先读这里。

---

## 1. 采样率：为什么是 857 kSPS 而不是 1 MSPS

### 硬约束链

STM32F103 的 ADC 时钟只能从 `PCLK2` 经 **/2 /4 /6 /8** 分频得到，上限 **14 MHz**。

```
T_conv = (采样时间 + 12.5) / f_ADCCLK        12-bit 模式
Ts 最小 = 1.5 周期
→ T_conv,min = 14 / 14MHz = 1.000 µs  → 理论 1.000 MSPS（f_ADCCLK = 14 MHz）
```

**但 14 MHz 拿不到**：72 MHz 系统 + USB 必须 `PLL = 72 MHz ÷ 1.5 = 48 MHz`，所以 `PCLK2 = 72 MHz`：

| 分频 | 结果 | 是否合法 |
|---|---|---|
| /2 | 36 MHz | ❌ 超 14 MHz |
| /4 | 18 MHz | ❌ 超 14 MHz |
| **/6** | **12 MHz** | ✅ |
| /8 | 9 MHz | ✅（更慢） |

```
12 MHz → T_conv = 14 / 12MHz = 1.1667 µs → 857.14 kSPS
```

> 要达到 1.000 MSPS 满速率必须把 `SYSCLK` 降到 56 MHz（HSE 8 M × 7），**但那样 48 MHz USB 就产生不了** —— 二选一。

**结论：标称 857 kSPS。** 任何文档、UI、宣传里都不许写 1 MSPS。

### 其他采样时间档（12 MHz / 12-bit）

| Ts（周期） | 采样率 | 源阻抗上限 | 用途 |
|---|---|---|---|
| 1.5 | 857 kSPS | **0.4 ~ 1.2 kΩ**（见下注） | 默认档 |
| 7.5 | 600 kSPS | ~5.9 ~ 19 kΩ（按同比例外推） | 前端源阻抗超标时 |
| 13.5 | 461.5 kSPS | 更高 | |
| 28.5 | 292.7 kSPS | 很高 | |
| 55.5 | 176.5 kSPS | 很高 | |
| 239.5 | 47.6 kSPS | 最高 | 慢变信号 |

> ⚠️ **源阻抗上限的出处不一致，取严不取宽。**
> AN3116 给出 1.5 周期 @14 MHz 约 1.2 kΩ；DS5319 的表值约 0.4 kΩ（更保守）。
> 两处差 3 倍 —— 按 **0.4 kΩ** 设计：前端增加一级缓冲，
> 以避免读数在高温/批次差异下变得不可信。
> **实板必须测**（见 `02-hardware.md` §9 第 9 项）。

### 双 ADC 交织：能到 1.71 MSPS，但只能「显示用」

快速交织（fast interleaved）让两个 ADC 以 7 个 ADCCLK 交替转换同一通道：

```
f_ADCCLK = 12 MHz → 上限 1.7143 MSPS（第三方实测 1713 kSPS）
```

**六个代价**：

1. 采样时间**必须 1.5 周期** → 源阻抗 ≤ 0.4~1.2 kΩ（按 **0.4 kΩ** 设计，见上文注），前端必须低阻运放直驱
2. **只能采同一通道** → 想同时看 SCL + SDA 就只能退回 857 kSPS/路
3. 两片 SAR **无出厂交织校准**，实测偶/奇样本直流失配 **~2 LSB** → 交织杂散落在 `fs/2 ± fin`，ENOB/SFDR 退化 0.5~1.5 bit
4. **DMA 必须配 32-bit**（低半字=ADC1、高半字=ADC2）；配成 16-bit 会**静默丢掉一半**（经典坑）
5. Ts=1.5 周期下 TUE 退化到约 ±4~5 LSB（有效约 10 bit）
6. 两 ADC 采样时刻相差 **500 ns**，去交织时时间轴必须按此重排，顺序反了时间轴整体错位半周期

**结论：交织模式只用于单线显示，绝不作为解码依据，也不用于谐波/THD 测量。**

## 2. I2C 解码：为什么 ADC 救不了 400 kHz

### 判据（由 I2C 规范最小时间推导，比"经验值"硬）

| 要素 | 所需采样率 |
|---|---|
| 解码比特值 / ACK | `S ≥ 1/tHIGH` |
| **判定 START/STOP**（需 SDA 翻转前后各一点都落在**同一个 SCL 高窗口**内） | `S ≥ 2/tHIGH` |

| I2C 速率 | tHIGH | `2/tHIGH` 下限 | 舒适（4×） | F103 857 kSPS |
|---|---|---|---|---|
| 100 kHz | 4.0 µs | 0.50 MSPS | 1.00 MSPS | ✅ **舒适**（8.6 点/bit，最坏高窗口 3.4 点） |
| 400 kHz | 0.6 µs | 3.33 MSPS | 6.67 MSPS | ❌ 差 **3.9×** |
| 1 MHz | 0.26 µs | 7.69 MSPS | 15.4 MSPS | ❌ 差 **9×** |

### 更麻烦的是「采样相位拍频」

当 `S/f = p/q`（最简分数）时，采样相位只有 **p 个离散值**：

| 场景 | S/f | 相位数 | 后果 |
|---|---|---|---|
| 857 k @ 100 kHz | 8.57 ≈ 60/7 | 60 | 覆盖良好 |
| 857 k @ 400 kHz | 2.14 ≈ **15/7** | **15**，间隔 0.167 µs（1/15 个比特周期） | 每 7 个比特一个固定循环 |
| 1 M @ 1 MHz | **1/1** | **1** | 采样点永远打在比特周期同一点，高低全凭运气 |

两颗晶振总有 ppm 差 ε，相位缓慢漂移，漂移周期 ≈ `1/(ε · f_bit)`：

> **ε = 40 ppm @ 400 kHz → 约 62 ms 走完一个比特周期**
> 表观症状：解码「时好时坏」以几十 ms 为周期闪烁。
> **这不是 bug，是采样相位拍频，软件补不了。**

### 所以：拆成两条通路

| | 模拟通路（ADC） | 协议通路（LM393 + TIM 捕获） |
|---|---|---|
| 时间分辨率 | 1.167 µs | **13.9 ns**（72 MHz） |
| 等效采样率 | 857 kSPS | **~72 MSPS** |
| 100 kHz | ✅ 保证 | ✅ 保证 |
| 400 kHz | ⚠️ 有条件（需主机占空接近 50% + 相位自对准） | ✅ **保证** |
| 1 MHz | ❌ 不支持 | ✅ **保证** |
| 时钟拉伸 | ✅ 能测（判据是绝对时间） | ✅ 免疫 |
| 电平裕量 / 上拉强度 / 振铃 | ✅ **独有能力** | ❌ 只有 0/1 |
| 边沿时间 tr | ❌ 单次模式下 1 µs 沿只有 1 点 | ⚠️ 14 ns 分辨率可测 |

> **400 kHz 的模拟通路要可用，三件套缺一不可**：采样相位自对准（锁到比特中点）+ 滞回 0.3/0.7·VDD 判决 + 中值 3 点去毛刺。
> 否则不要写进宣传。

### 等效时间采样（ETS）：能做但不能信

用数字通路 13.9 ns 触发，可把 857 kSPS 等效成 **~72 MSPS / 14 ns 分辨率**；帧平均 N 次再得 `0.5·log2(N)` bit 幅度增益（16 次 +2 bit）。

**失效场景（必须写进声明）**：非周期帧 / 内容变化、任意时长的时钟拉伸、仲裁、NACK、总线错误、上电瞬间一次性毛刺、动态地址。

> **ETS 只能用于「看边沿形状」，绝不能用它证明「总线正常 / 没有毛刺」** ——
> 它能合成出**看起来合理但从未发生过**的波形。

## 3. 存储：8 KB 就是天花板

`F103C8T6 = 64 KB Flash / 20 KB SRAM`，**没有 FSMC**（中容量型号），SRAM 无法外扩。

### 20 KB 的现实预算

| 项 | 占用 |
|---|---|
| 采集 DMA 环（`uint16_t ring[4096]`） | **8 KB** |
| 协议 RX 环形缓冲 | 1 KB |
| USB CDC 栈状态 + APP 缓冲 | 1~2 KB（**ST 例程默认各 2 KB，必须改小**） |
| 主栈 | 1~2 KB |
| TFT 帧缓冲（若上屏） | 128×160 单色 **2.5 KB**（128×160÷8 = 2560 B；彩色需分块刷） |
| 应用全局 + 定点查找表 | 2~4 KB |
| **协议帧 / 命令缓冲** | 0.5~1 KB |
| **余量** | **~2~4 KB** |

> **Flash 侧**：ST HAL + USB CDC 库约 20~35 KB，再加 UI/协议/解码逻辑，**64 KB 有顶满风险** → 优先裸机 / LL 库，或直接换 **F103C8 的 128 KB 兄弟 CB**。

### 深度能存多久

| 配置 | 深度 | 时间（857 kSPS） |
|---|---|---|
| 单通道 12-bit（u16） | 4096 点 | 4.78 ms |
| 双通道 12-bit 各 u16 | 2×2048 点 | 2.39 ms |
| 双通道 8-bit | 2×4096 点 | 4.78 ms |
| 交织单通道 1.71 MSPS（仅显示） | 4096 点 | 2.39 ms |

### 这够用吗？—— 对 I2C 够

标准 2 字节寄存器写 ≈ 27 bit：

| I2C 速率 | 一次事务耗时 | 4.78 ms 窗口内可采集的事务数 |
|---|---|---|
| 100 kHz | 270 µs | **~17 个** |
| 400 kHz | 68 µs | **~70 个** |

**深存储路线在 C8 上直接归零**，必须用定点、分段采集、降采样和「采集-上传-清空」的循环模式。
教科书式的「1 M 点深存储」、「1024 点 float FFT」（复数数组就要 8 KB）全部不成立。

## 4. 链路：任何链路都塞不下满速流

| 链路 | 实测吞吐 | RAW u16 持续上限 |
|---|---|---|
| **USB CDC**（若核心板 USB 可用） | 500–900 KB/s | 250–450 kSa/s |
| **UART 921600**（外接 CH340 模块） | 92 KB/s | ~46 kSa/s |
| UART 115200 | 11.5 KB/s | ~5.8 kSa/s |

原始流 `857 kSPS × 2 B = 1.71 MB/s` —— **比 USB CDC 上限还高**，比 921600 串口高 18 倍。

**所以「1 MSPS 原始数据实时上传」必须从所有 UI / 文档承诺里删掉。**
实时视图用 MINMAX 抽点，无损查看用 4096 点单次采集。

## 5. 其他硬约束

| 约束 | 后果 |
|---|---|
| **无 DAC、无模拟比较器** | 触发/偏置电平只能用 PWM+RC 或外置电位器；硬件边沿触发只能靠 ADC 模拟看门狗（越限中断，**不精确且停不下采样**）或外置 LM393 |
| **48 脚封装无 VREF+ 引脚** | 3.3V 数字/AFE 噪声直接成为 ADC 基准 → **12-bit 绝对精度做不到**，需低噪 LDO + 滤波，可用 `Vrefint` 反算修正 |
| **16 位定时器 @72 MHz** | `PSC=0` 时最低触发率 1098.6 Hz；采样周期只能整数分频、量化步进 **13.9 ns** → 无精密测频/高精度时基 |
| **无 FPU** | 禁 `f32` 进采样内环；浮点全部留上位机 |
| **857 kSPS → 每样本 84 周期** | **禁止逐样本中断**，必须 DMA + 块中断（2048 点/块时块率仅 419 Hz） |
| **ADC2 无 DMA 请求通道**（中容量型号限制） | 双 ADC 模式下只能借 `ADC1_DR` 组合寄存器经 ADC1 的 DMA 搬出 |
| **DMA 不能访问 Flash** | 波形表/常数表不能直接 DMA 搬出 |

## 6. 一页纸总结

### ✅ 能做

- I2C 协议解码 **100 kHz / 400 kHz / 1 MHz 全部可靠**（数字通路）
  > ⏳ **上条为数字通路的设计目标，尚非已实现能力**：边沿时间戳缓冲
  > （`firmware/Hardware/src/tim_capture.c`）与解码器（`firmware/App/i2c_decode.c`）
  > **均尚未创建**，见 [05-roadmap.md](05-roadmap.md) §P2。本文第 2 节的采样率判据
  > 与 13.9 ns 时间分辨率成立，但上条在实现完成前不应作为已交付能力引用。
- 双通道同步 **857 kSPS**、单通道交织 1.71 MSPS（仅显示）
- 单次采集 **4096 点**，USB 传 8 KB ≈ 12 ms
- 模拟观察 **≤ 100 kHz** 保证
- 连续流 **150–250 kSa/s** 等效（USB）/ 27 kSa/s（921600）—— 设计值按链路留 40% 余量，见 [03-protocol.md](03-protocol.md) §6.2
- 电平裕量、上拉强度、振铃、边沿形状（**逻辑分析仪给不了的**）
- 频率 / 占空比 / Vpp / RMS / 上升与下降时间 / 过冲与下冲 / 高电平脉宽 / 边沿数（定点）

### ❌ 不能

- 1 MSPS 与 USB 并存
- 400 kHz / 1 MHz 的**模拟边沿时序**与 `tSU;DAT` / `tr` 合规性验证
- 深存储、外扩 SRAM、2048 点以上 float FFT
- THD / SFDR / ENOB 测量
- 12-bit 绝对精度计量
- 以太网 / 远程采集
- 带宽 > 0.5 MHz
- AI 程控量程（SW2/SW3 是机械拨动开关，需改板）

## 7. 硬件升级路线（若将来必须突破）

| 需求 | 方案 | 成本 |
|---|---|---|
| 400k/1M 的模拟边沿细节 | STM32G431/G474（4–5 MSPS，400 kHz 得 10–12.5 点/bit） | 换 MCU + 重画板 |
| 100% 可靠的协议通道，不动主控 | 加一颗 **RP2040**（PIO 125 MHz 做协议） | ~10 元 |
| 深存储 | 换带 FSMC 的大封装（F103RC/ZE）或 `23LC1024` SPI SRAM | 仅适合非实时回放 |
| 网络 | 外挂 W5500 / ENC28J60 SPI 模块 | 后期 |

> **上层框架（命令层 / 协议 / 上位机解码 / 泳道显示 / MCP 工具）可原样保留，只换采集层。**
> 这是把协议做成独立真相源的直接回报。
